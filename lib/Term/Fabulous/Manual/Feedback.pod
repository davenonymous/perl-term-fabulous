=head1 NAME

Term::Fabulous::Manual::Feedback - Progress bars, spinners and toasts

=head1 DESCRIPTION

This page is part of L<Term::Fabulous::Manual>. Previous page: L<Term::Fabulous::Manual::Forms>. Next page: L<Term::Fabulous::Manual::Charts>.

This page covers the widgets that tell the user what the program is
doing: a L<progress bar|/PROGRESS BARS> for a task whose extent is
known, or not, a L<spinner|/SPINNERS> for one that just takes a
while, and L<toasts|/TOASTS AND ALERTS> for messages that must not
interrupt the user. They take no input; the program sets their state,
from a timer, a process or a listener, and they draw themselves. The
ones that move do so on the application's clock, without a timer of
their own (see L</ANIMATION>).

The reference pages are the class pages: L<Term::Fabulous::Widget::ProgressBar>,
L<Term::Fabulous::Widget::Spinner> and L<Term::Fabulous::Widget::Toast>.
The class the first two share, L<Term::Fabulous::Widget::Display>, is
the base of every widget that paints itself from its own state, and
the one to derive from for a feedback widget of your own
(L<Term::Fabulous::Manual::CustomWidgets/A widget that draws itself>).

=head1 PROGRESS BARS

A L<Term::Fabulous::Widget::ProgressBar> shows a value between C<min>
and C<max> as a bar filled from the left, with the percentage (or a
label of your own) next to it. The program sets the value as the work
goes on:

	use Term::Fabulous::Widget::ProgressBar;

	my $progress = Term::Fabulous::Widget::ProgressBar->new(
		max    => $total_bytes,
		layout => { sizing => { width => sizing_grow() } },
	);
	$progress->value($bytes_so_far);    # from a timer or a process

The picture shows the forms a bar can take
(F<examples/widgets/progress-bar.pl>):

=begin html

<p><img src="https://raw.githubusercontent.com/davenonymous/perl-term-fabulous/v0.01/screenshots/widget-progress-bar.svg" alt="Progress bars: a block bar at 42 percent, one with the value inside, a thin line bar, a striped bar, a bar of three colored segments, an indeterminate bar with its runner, and a two-row ASCII bar"></p>

=end html

=over

=item *

B<Styles.> C<block> (the default) fills cells with blocks and moves in
eighths of a cell; C<line> draws a thin line like a slider's track;
C<ascii> uses C<#> and C<->. C<fill_glyph>, C<track_glyph> and
C<stripe_glyph> replace the glyphs of a style. A layout that makes the
bar more than one row high gives a thicker bar.

=item *

B<The label.> The percentage by default, right of the bar;
C<< value_position => 'left' >> or C<'inside'> move it, and
C<value_format> formats it as a C<sprintf> string of the percentage or
with code that gets the value, for C<12 of 50 MB>. C<show_value =E<gt> 0>
hides it.

=item *

B<Stripes.> C<striped> alternates two glyphs along the filled part,
and C<animated> moves them: the bar then shows that the task is still
running even while its value does not change.

=item *

B<Indeterminate.> A task whose extent is not known yet gets
C<< indeterminate => 1 >>: a runner bounces from end to end and the
label is hidden. Switch it off, set C<max> and the value once the
extent is known.

=item *

B<Segments.> C<segments> stack several values in one bar, each in its
own color: the used, reserved and free parts of a disk, the passed,
failed and skipped tests. C<separated> leaves a cell of track between
them, and the bar's C<value> is their sum.

=back

The colors are C<color> (the filled part), C<track_color>,
C<text_color> and, for a label inside the bar, C<inside_text_color>;
the program changes C<color> to show a state, for example red below a
threshold. In KDL:

=for highlighter language=kdl

	ProgressBar "download" {
		max 2048
		value 860
		style "line"
		sizing width=grow
	}

=head1 SPINNERS

A L<Term::Fabulous::Widget::Spinner> shows that the program is busy
with something it cannot measure: connecting, waiting, loading. It
cycles through the frames of its style next to a label:

=for highlighter language=perl

	use Term::Fabulous::Widget::Spinner;

	my $spinner = Term::Fabulous::Widget::Spinner->new( label => 'Connecting' );
	$status_row->add_child($spinner);
	# later:
	$spinner->stop;
	$status_row->remove_child($spinner);

The styles come in three sizes: one cell (C<dots>, the default, made
of Braille patterns; C<line>, C<arc>, C<circle>, C<arrow>, C<box>,
C<pulse>, C<bar>), a few cells (C<dots3>, C<bounce>, C<wave>) and
three rows (C<ring>). C<frames> of your own, of one or several rows,
replace the style's, and C<interval> sets the pace. C<stop> freezes
the spinner at its first frame; a stopped spinner costs nothing. The
picture shows every style (F<examples/widgets/spinner.pl>):

=begin html

<p><img src="https://raw.githubusercontent.com/davenonymous/perl-term-fabulous/v0.01/screenshots/widget-spinner.svg" alt="Spinners in every style, each with its name: dots, line, arc, circle, arrow, box, pulse and bar in one cell, dots3, bounce and wave in several, and the three-row ring; a stopped one and one with frames of its own"></p>

=end html

In KDL:

=for highlighter language=kdl

	Spinner "busy" {
		style "arc"
		label "Loading"
	}

=head1 TOASTS AND ALERTS

A L<Term::Fabulous::Widget::Toast> is a short message in a corner of
the screen that goes away by itself: a box with an icon, a title, a
message and a close mark, in the color of its kind (C<info>,
C<success>, C<warning> or C<danger>). C<show> floats it over
everything else, where it lines up below the toasts shown there
before, and takes it away after C<timeout> seconds; a click on the
close mark or C<hide> takes it away at once. Toasts take no focus and
no keys:

=for highlighter language=perl

	use Term::Fabulous::Widget::Toast;

	$save->on( Activate => sub ($event) {
		save();
		Term::Fabulous::Widget::Toast->new( kind => 'success', title => 'Saved', message => 'Written to disk.' )->show($ui);
		return;
	} );

An C<important> toast is filled with its color, for messages that must
not be missed; C<< timeout => undef >> keeps a toast until it is
closed; C<position> chooses the corner (or the top or bottom center),
and every corner stacks its own toasts. The same widget is an I<alert>
when it is added to the layout as a child instead of being shown: it
then stays where it is put, with or without a close mark. The picture
shows toasts of every kind, an important one and an alert box
(F<examples/widgets/toast.pl>):

=begin html

<p><img src="https://raw.githubusercontent.com/davenonymous/perl-term-fabulous/v0.01/screenshots/widget-toast.svg" alt="Toasts stacked in the top right corner: an info, a success and a warning toast with titles, messages and close marks, a filled danger toast in the bottom right corner, and an alert box inside the form"></p>

=end html

A toast fires C<Close> (L<Term::Fabulous::Event::Close>) when it goes,
whichever way. In KDL a toast is an alert box inside its parent:

=for highlighter language=kdl

	Toast "unsaved" {
		kind "warning"
		message "You have unsaved changes."
		closable #false
	}

=head1 ANIMATION

Spinners, and progress bars that are C<indeterminate> or C<animated>,
move by themselves. They need no timer: a moving widget reads the application's
clock (L<Term::Fabulous/now>) and asks for a frame at the moment its
next frame is due (L<Term::Fabulous/request_frame_at>); Term::Fabulous
draws it at the next tick of its frame timer, and nothing is drawn in
between. In a test, the C<clock> parameter of L<Term::Fabulous/new>
moves the animation on, and the screenshot tools of
L<Term::Fabulous::Examples> run it on a virtual clock. A widget of your
own animates the same way; see
L<Term::Fabulous::Widget::Display/ANIMATION>.
